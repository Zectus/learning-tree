=== SECTION 1: Ungrouped frequency, relative frequency, and cumulative tables ===

Raw data rarely speak for themselves. If a librarian records the number of books checked out by \(n = 20\) students in a single afternoon,
\[
2,\; 0,\; 1,\; 3,\; 2,\; 1,\; 2,\; 0,\; 4,\; 2,\; 1,\; 3,\; 2,\; 0,\; 1,\; 2,\; 3,\; 1,\; 2,\; 3,
\]
it is hard to tell at a glance what proportion of students checked out at most two books or whether checking out one book is more common than checking out three. Organizing repeated values into a frequency distribution compresses the raw list into a structured summary without losing any information about how often each distinct value occurs.

[CALLOUT]
id: freq-definitions
label: Definition
title: Frequency, relative frequency, and cumulative frequencies
tone: key

Let a dataset of size \(n\) take distinct values (or classes) indexed by \(j = 1, 2, \dots, k\).

(1) The frequency (or count) \(f_j\) is the number of observations in category or value \(j\), so \(\sum_{j=1}^k f_j = n\).
(2) The relative frequency \(p_j = f_j / n\) is the proportion of observations in category \(j\). Because the categories are mutually exclusive and cover every observation, \(\sum_{j=1}^k p_j = 1\) (up to rounding error when decimals are rounded).
(3) When the values are ordered from smallest to largest, the cumulative frequency \(F_j = \sum_{m=1}^j f_m\) is the total number of observations at or below value \(j\), and the cumulative relative frequency \(P_j = F_j / n = \sum_{m=1}^j p_m\) is the corresponding running proportion, ending at \(F_k = n\) and \(P_k = 1\).
[/CALLOUT]

Applying [REF: freq-definitions | these definitions] to the \(n = 20\) library checkouts produces the following ungrouped frequency table.

[TABLE]
Books checked out (\(x_j\)) | Frequency (\(f_j\)) | Relative frequency (\(p_j\)) | Cumulative frequency (\(F_j\)) | Cumulative relative frequency (\(P_j\))
0 | 3 | 0.15 | 3 | 0.15
1 | 5 | 0.25 | 8 | 0.40
2 | 7 | 0.35 | 15 | 0.75
3 | 4 | 0.20 | 19 | 0.95
4 | 1 | 0.05 | 20 | 1.00
[/TABLE]

Verify every consistency check immediately: \(3 + 5 + 7 + 4 + 1 = 20 = n\), and \(0.15 + 0.25 + 0.35 + 0.20 + 0.05 = 1.00\). The cumulative columns answer threshold questions instantly: \(F_2 = 15\) students—meaning \(P_2 = 0.75\), or \(75\%\)—checked out at most \(2\) books, while \(1 - P_2 = 0.25\) (\(25\%\)) checked out more than \(2\) books.

Notice the explicit condition in [REF: freq-definitions.3 | item (3)]: cumulative frequencies require an intrinsic ordering, so they are valid only for variables measured on at least an ordinal scale (ordinal, interval, or ratio). If you build a frequency table for a nominal variable such as blood type (\(\text{A}, \text{B}, \text{AB}, \text{O}\)), frequencies and relative frequencies make complete sense, but "cumulative frequency up to type \(\text{B}\)" changes completely if you reorder the rows alphabetically versus by frequency. Never add cumulative columns to a nominal table.

=== SECTION 2: Grouped frequency distributions, boundaries, and bin choices ===

When a variable is continuous (like commute time in minutes) or discrete with dozens of distinct values (like exam scores from \(0\) to \(100\)), listing every unique value in its own row produces a huge table where most frequencies are \(0\) or \(1\). To reveal the overall pattern, we partition the numeric range into contiguous, non-overlapping intervals called classes (or bins).

Building a clean grouped table requires precision about where one class ends and the next begins. Suppose commute times are recorded to the nearest tenth of a minute, and we group them into ten-minute intervals. If you write "0–10" and "10–20", it is ambiguous which class receives an observation of exactly \(10.0\) minutes. Resolving this ambiguity consistently separates stated class limits from exact class boundaries.

[CALLOUT]
id: grouped-class-anatomy
label: Definition
title: Class boundaries, width, midpoint, and boundary convention
tone: key

When grouping a quantitative variable into \(k\) contiguous intervals:

(1) Under the left-closed, right-open convention \([L_j, U_j)\), an observation \(x\) belongs to class \(j\) if and only if \(L_j \le x < U_j\). Here \(L_j\) is the lower class boundary and \(U_j\) is the upper class boundary, and adjacent classes share exact boundaries (\(U_j = L_{j+1}\)) with no overlap and no gap. (The final class may be written \([L_k, U_k]\) if an observation lands on \(U_k\).)
(2) When rounded discrete data are written with separated stated limits such as \(10\text{–}19\) and \(20\text{–}29\) (rounded to integers), the exact class boundaries sit halfway across the rounding gap—here \(9.5\) to \(19.5\) and \(19.5\) to \(29.5\).
(3) The class width is the distance between exact boundaries: \(w_j = U_j - L_j\).
(4) The class midpoint (or class mark) is the center of the interval: \(m_j = (L_j + U_j) / 2\).
[/CALLOUT]

Watch out for a classic width mistake on integer-limited tables: for stated integer limits \(10\text{–}19\), the width is not \(19 - 10 = 9\). Because integers \(10, 11, \dots, 19\) span ten whole numbers—matching exact boundaries \(9.5\) to \(19.5\)—the true class width is \(19.5 - 9.5 = 10\). Using [REF: grouped-class-anatomy.1 | the interval notation \([L_j, U_j)\)] avoids rounding-gap confusion altogether because the exact boundaries are stated directly.

How many classes \(k\) should you choose? Too few classes (say \(k = 2\) or \(3\)) oversmooth the data, erasing peaks, gaps, and asymmetry. Too many classes (say \(k = 30\) for \(n = 40\) observations) scatter points into noisy, mostly empty bins. Two simple heuristics provide reasonable starting points for a dataset of size \(n\):
- The square-root rule: \(k \approx \sqrt{n}\).
- Sturges' rule: \(k \approx 1 + \log_2 n = 1 + \dfrac{\ln n}{\ln 2}\).

For \(n = 40\) workers' commute times, \(\sqrt{40} \approx 6.3\) and \(1 + \log_2(40) \approx 1 + 5.32 = 6.32\). Both suggest roughly \(5\) to \(7\) classes. Neither formula is a rigid law: choosing \(k = 5\) clean ten-minute intervals spanning \(0\) to \(50\) minutes is far more readable than \(6\) awkward intervals of width \(8.33\) minutes.

Here is the resulting grouped frequency table for the \(n = 40\) commute times (in minutes):

[TABLE]
Class interval (min) | Midpoint (\(m_j\)) | Width (\(w_j\)) | Frequency (\(f_j\)) | Relative freq (\(p_j\)) | Cumulative freq (\(F_j\)) | Cumulative rel freq (\(P_j\))
\([0, 10)\) | 5 | 10 | 4 | 0.10 | 4 | 0.10
\([10, 20)\) | 15 | 10 | 10 | 0.25 | 14 | 0.35
\([20, 30)\) | 25 | 10 | 14 | 0.35 | 28 | 0.70
\([30, 40)\) | 35 | 10 | 8 | 0.20 | 36 | 0.90
\([40, 50)\) | 45 | 10 | 4 | 0.10 | 40 | 1.00
[/TABLE]

Under our convention, a commute time of exactly \(20.0\) minutes falls into \([20, 30)\), not \([10, 20)\). Grouping trades individual precision for clarity: we can read directly that \(70\%\) of workers commute less than \(30\) minutes, even though we no longer see the exact individual minutes inside \([20, 30)\).

=== SECTION 3: Unequal class widths and frequency density ===

Real-world reports—especially for incomes, firm sizes, or age brackets—frequently use unequal class widths because the upper tail stretches over a much wider numerical span than the lower end. Suppose a survey records annual incomes (in thousands of dollars) for \(n = 100\) households using four intervals: \([0, 20)\), \([20, 40)\), \([40, 80)\), and \([80, 160)\). Look carefully at the frequencies:
- \([0, 20)\): \(f_1 = 16\)
- \([20, 40)\): \(f_2 = 28\)
- \([40, 80)\): \(f_3 = 36\)
- \([80, 160)\): \(f_4 = 20\)

At first glance, \([40, 80)\) seems more crowded than \([20, 40)\) because \(36 > 28\). That comparison is misleading! The interval \([40, 80)\) is twice as wide (\(w_3 = 40\)) as \([20, 40)\) (\(w_2 = 20\)), so it collects households over twice as large a span of income. On average, \([40, 80)\) contains only \(36 / 40 = 0.90\) households per thousand-dollar unit, whereas \([20, 40)\) contains \(28 / 20 = 1.40\) households per thousand-dollar unit. To compare concentration fairly across unequal widths, we divide relative frequency by class width.

[CALLOUT]
id: frequency-density
label: Definition
title: Frequency density
tone: key

For a grouped class \(j\) with relative frequency \(p_j = f_j / n\) and class width \(w_j = U_j - L_j > 0\), the frequency density (also called relative frequency density) is
\[
d_j = \frac{p_j}{w_j} = \frac{f_j}{n \, w_j}.
\]
Its units are proportion per unit of \(x\). Multiplying each class's density by its width recovers its relative frequency, \(d_j w_j = p_j\), so the total density-times-width sum across all \(k\) classes always equals \(1\):
\[
\sum_{j=1}^k d_j w_j = \sum_{j=1}^k p_j = 1.
\]
[/CALLOUT]

Let us complete the household income table using [REF: frequency-density | the density formula].

[TABLE]
Income class (\(\$1000\text{s}\)) | Width (\(w_j\)) | Freq (\(f_j\)) | Rel freq (\(p_j\)) | Density (\(d_j = p_j / w_j\)) | Area check (\(d_j w_j\))
\([0, 20)\) | 20 | 16 | 0.16 | 0.0080 | 0.16
\([20, 40)\) | 20 | 28 | 0.28 | 0.0140 | 0.28
\([40, 80)\) | 40 | 36 | 0.36 | 0.0090 | 0.36
\([80, 160)\) | 80 | 20 | 0.20 | 0.0025 | 0.20
[/TABLE]

Verify the total: \(20(0.0080) + 20(0.0140) + 40(0.0090) + 80(0.0025) = 0.16 + 0.28 + 0.36 + 0.20 = 1.00\). The density column exposes the true concentration pattern immediately: households are most densely packed in \([20, 40)\) (\(d_2 = 0.0140\) per thousand dollars), followed by \([40, 80)\) (\(0.0090\)), \([0, 20)\) (\(0.0080\)), and finally the sparse upper tail \([80, 160)\) (\(0.0025\)). In the next lesson, frequency density will serve as the exact vertical height needed to draw honest histograms with unequal bin widths.

=== SECTION 4: Constructing and reading ogives ===

A cumulative relative frequency table gives exact running proportions at every upper class boundary \(U_j\). What if a planner asks for the approximate fraction of commuters whose trip takes less than \(24\) minutes, or wants to find the travel-time cutoff below which \(60\%\) of commuters fall? Because \(24\) lies inside the class \([20, 30)\), the table alone gives only the bounds \(0.35\) (at \(20\) min) and \(0.70\) (at \(30\) min). Plotting cumulative relative frequency against the upper class boundaries and connecting consecutive points with straight line segments creates an ogive (a cumulative frequency polygon), which turns those discrete boundary values into a continuous piecewise-linear curve.

[CALLOUT]
id: ogive-construction
label: Definition
title: Ogive construction and within-class linear interpolation
tone: key

To construct a cumulative relative frequency ogive from grouped classes \([L_1, U_1), \dots, [L_k, U_k)\) with cumulative relative frequencies \(P_1, \dots, P_k\):

(1) Anchor the curve on the horizontal axis at the lowest lower boundary: \((L_1, 0)\).
(2) Plot one point at each upper class boundary: \((U_j, P_j)\) for \(j = 1, \dots, k\), ending at \((U_k, 1)\).
(3) Connect consecutive plotted points with straight line segments.

Assuming observations are spread roughly uniformly inside class \([L_j, U_j)\) (where \(P_0 = 0\)), the ogive estimates the cumulative proportion below any threshold \(c \in [L_j, U_j]\) by
\[
\hat{P}(c) = P_{j-1} + \frac{c - L_j}{U_j - L_j}\,(P_j - P_{j-1}),
\]
and estimates the inverse threshold \(c\) for a target cumulative proportion \(q \in [P_{j-1}, P_j]\) by solving for \(c\):
\[
\hat{c}(q) = L_j + \frac{q - P_{j-1}}{P_j - P_{j-1}}\,(U_j - L_j).
\]
[/CALLOUT]

Why must the points be plotted at the upper class boundaries \(U_j\) rather than at the class midpoints \(m_j\)? Because by definition, \(P_j\) is the proportion of all observations strictly less than \(U_j\) (accumulating the entire class \([L_j, U_j)\)). Plotting \(P_j\) at the midpoint \(m_j\) would falsely claim that all observations in \([L_j, U_j)\) had already occurred halfway through the interval, shifting the entire curve to the left. Similarly, anchoring at \((L_1, 0)\) states the exact fact that zero observations fall below the start of the first class.

Let us apply [REF: ogive-construction | the ogive formulas] to our \(n = 40\) commute-time table, whose vertices are \((0, 0)\), \((10, 0.10)\), \((20, 0.35)\), \((30, 0.70)\), \((40, 0.90)\), and \((50, 1.00)\).
- Forward read (proportion below \(c = 24\) min): Since \(24\) lies in \([20, 30)\), where \(P_2 = 0.35\) and \(P_3 = 0.70\), we move \((24 - 20)/(30 - 20) = 0.4\) of the way across the bin, adding \(0.4 \times (0.70 - 0.35) = 0.14\) to \(0.35\):
\[
\hat{P}(24) = 0.35 + \frac{24 - 20}{30 - 20}(0.70 - 0.35) = 0.35 + 0.14 = 0.49.
\]
So roughly \(49\%\) of commuters travel less than \(24\) minutes.
- Inverse read (time threshold for the lowest \(q = 0.60\), or \(60\%\), of commuters): Since \(0.60\) lies between \(P_2 = 0.35\) and \(P_3 = 0.70\), the cutoff sits inside \([20, 30)\). We need to climb \(0.60 - 0.35 = 0.25\) out of the class's vertical rise \(0.70 - 0.35 = 0.35\):
\[
\hat{c}(0.60) = 20 + \frac{0.60 - 0.35}{0.70 - 0.35}(30 - 20) = 20 + \frac{5}{7}(10) \approx 27.14\text{ min}.
\]

Look closely at the slope of each straight segment of an ogive. Over class \([L_j, U_j)\), the vertical change is \(P_j - P_{j-1} = p_j\) and the horizontal change is \(U_j - L_j = w_j\), so the slope of the \(j\)-th ogive segment is
\[
\frac{P_j - P_{j-1}}{U_j - L_j} = \frac{p_j}{w_j} = d_j,
\]
which is precisely [REF: frequency-density | the frequency density] of that class! This geometric link explains why an ogive is always non-decreasing (since \(d_j \ge 0\)), rises steeply where observations are concentrated, flattens where observations are sparse, and stays completely flat across any empty class (\(f_j = 0\)). Keep in mind also that ogive estimates between boundaries are approximations built on the assumption of uniform spread inside each bin; if all observations in \([20, 30)\) actually clustered near \(29\) minutes, linear interpolation would overestimate the proportion below \(24\) minutes.
