# Fresh-author tree prompt comparison

The user requested actual prompt testing with fresh perspectives after distinguishing app compatibility tests from evidence about generated trees. This study compares the pre-rebuild tree prompt at `53afa70` with the rebuilt source frozen before authoring. It does not reuse the five hand-authored specimens from the earlier rebuild.

Four subjects cover two topic flows (Spanish calculus; reliable HTTP retries) and two file flows (a synthetic diagnostic-assay argument; a synthetic archive policy). There are two fresh authors per condition and subject: 16 planned first completed trees. Exact source snapshots, rendered prompts, matched completed calibration records, attachments, task assignments and hashes are retained. Initial wrapper instructions give no tree length, node count or preferred graph shape. A saved local JSON file fulfills the delivery requirement. Necessary unresolved questions are recorded as blockers, not silently answered by authors.

Generation isolates post-calibration tree design: both conditions receive the same concrete prior exchanges and confirmed destination. It does not measure adaptive calibration behavior. Each author has fresh history (`fork_turns="none"`) and may read only its assigned input and attachment. Authors may self-review and validate their own tree as instructed by the prompt, but receive no outside feedback, other variants, rubric, or other outputs. All first completed outputs are retained without selection or replacement.

The reviewer rubric was frozen before generation (hash in manifest.json). Two fresh reviewers per subject see all four trees under anonymous labels. The second presentation rotates the first by two positions, putting each condition in every position across the two reviewers. They receive the neutral destination, calibrated abilities, and source, but neither generation prompt nor condition labels. Review packets use the app's imported graph, because transitive edges are automatically removed before lesson generation. Original raw outputs are retained. Each tree is rated on correctness/destination, prerequisite sufficiency, teachable scope/progression, and lesson handoff, each on an anchored integer 1–5 scale. Reviewers give concrete node-level findings, rankings, confidence, and possible counterevidence. They are instructed to judge usable paths rather than verbosity, node count, or graph shape.

All subagents inherit the session's model and reasoning configuration; no model or effort override is used. Reviewer histories are fresh and separate from authors. Blinding is procedural through allowed-file instructions, not a filesystem security boundary; stylistic clues may still reveal likely provenance. Multiple ratings of the same output are not independent author samples. Scores are descriptive, not a statistical demonstration of human learning or cross-model generality.

Aggregate by averaging the four criteria within each tree/reviewer, then equal-weighting authors and reviewers within each subject and subjects across the study. Show per-subject results, individual-output variation and concrete repairs alongside any overall mean. Count a reviewer-level condition preference by comparing the means of its two outputs per condition; report ties explicitly. Do not count those preferences as independent subject replications.

Inspect alleged substantive failures against actual scopes, calibration and supplied source before editing production instructions. Preserve the original reports if a reviewer makes a factual mistake; record any verified correction separately. If a revision is justified, freeze it and test it on new generations, separating reused references and new outputs. Do not present untested cleanup as the tested source or discard an unfavorable result.
