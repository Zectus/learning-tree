# Small pilot: monolithic prompt versus skill-style files

Only idea 1 is tested. Four fresh GPT 6.1 Sol low writers: two per condition, same limit_intuition node and exact current coherent teaching content, Spanish output. First complete outputs only, no regeneration or quality selection. No author may delegate, receive evaluator feedback, or revise from it; idea 2 is expressly excluded. Author self-check already present in the original prompt remains in both conditions.

Monolithic has one full input file. Modular has SKILL.md with topic/delivery/reader language/context plus a short file-routing workflow, and six references: planning, format, graphs, teaching, questions, final review. All original text is preserved verbatim and reconstructs byte-identically; metadata/routing is added and context is moved earlier. Thus this is a test of skill-style organization and staged retrieval, not a pure file-count intervention. Files read are recorded in author final responses. It does not measure automatic context removal or actual billed token savings.

Freeze this plan, source hashes, launch order and all assignments before generation. Four fresh blind gpt-6-luna graders, fork none, no effort override. Exact prior five-criterion rubric adapted only from three to two labels. Each grader sees one output per condition, never the prompts or packaging identity. Two panels receive monolithic first, two modular first. Every output appears twice, once in each position; all four cross-condition output pairings occur once. Model scores do not measure human learning.

Separately verify every answer key, central reasoning, app parsing and graph expressions. Do not repair authored outputs or send feedback to authors. Aggregate equal-weight criteria, preserve raw judgments and preferences, flag arithmetic/factual errors transparently. This one-node two-output-per-condition pilot can identify promising differences or problems, not demonstrate broad superiority. Keep the app's production prompt unchanged.
